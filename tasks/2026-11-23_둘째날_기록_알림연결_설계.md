# 첫 기록 다음: 둘째 날 기록과 알림 연결 (설계안)

2026-11-23. 대표: "두 번째 기록과 알림 연결 개선안을 설계해 줘."
앞선 설계: `tasks/2026-11-07_새회원_첫기록_흐름_설계.md` — 첫 기록 목표 40% 를 넘었다(아래 1절). 이제 그다음 칸.

## 1. 숫자 (관제탑 「🌱 성장」, 2026-11-23 운영)

| 알림이 연결된 회원 | **27%** (최근 30일 기록한 233명 중 64명) | 플레이 앱으로 연 회원 432명 |

  11/7 설계의 두 번째 목표("첫 기록한 사람의 절반")에 못 미친다. 두 숫자의 가입 구간이 달라서 어림이다.

## 2. 지금 흐름 (첫 기록 뒤)

1. 첫 기록 결과 창 (`maybeShowFirstRecordResult`, `js/app-core.js`)
   - 플레이 앱: "다음 끼니 때 알려 드릴까요?" → **알림 받기** (`enableFirstRecordReminder`)
     → 기기 알림 허락 → `settings.reminderPreference = { enabled, category: 'diet', hourKst }`.
     시각은 `nextMealReminderHour` (11시 전 → 12시, 17시 전 → 18시, 그 뒤 → 다음 날 12시).
   - 웹: 홈 화면 앱 설치만 권한다(플레이 앱은 권하지 않는다, 대표 2026-11-02).
   - 웹 앱을 이미 설치했으면 칸이 없다.
2. 다음 날: 알림을 켠 사람만, 정한 시각에 그날 기록이 없으면 푸시 한 통 (`selectHabitReminderRecipients`).
3. 하루를 통째로 빠뜨리면 그다음 날 메일 (`runScheduledReEngagementSweep`, 공백 2일). 문구는 오래 기록한 회원과 같다 — "어제 기록이 비어 있었어요".
4. 식단 탭 맨 위 빨간 상자("다음 식사를 기다리지 마세요")는 **기록이 0인 회원에게만** 보인다 (`_firstRecordNudgeUid`, `hasStartedRecording`). 첫 기록을 하면 사라지고, 기록이 1번인 회원에게는 아무 안내도 없다.

## 3. 모르는 것 — 먼저 잴 것

1절의 30% 가 어디서 새는지 지금 자료로는 가를 수 없다.

- 결과 창에서 **알림 받기를 눌렀는지, 기기 허락에서 거절했는지**는 서버에 남지 않는다. 11/7 에 가입 안내 단추를 서버에 남긴 것(`completeOnboarding({ choice })`)과 같은 처지다.
- 그래서 "알림을 켠 첫 기록자" 와 "안 켠 첫 기록자" 의 둘째 날 기록률을 비교할 수 없다. 알림이 효과가 있는지조차 모른다.
- 플레이 앱(안드로이드 13 이상)에서 알림 허락이 실제로 뜨고 통과되는지도 숫자로 본 적이 없다. 1.0.14 에서 `POST_NOTIFICATIONS` 와 위임 창을 넣었지만, 432명 중 연결 64명은 낮다.

## 4. 바꿀 것 — 네 가지 (순서대로)

### 4-0. 첫 기록 결과 창의 선택을 서버에 남긴다 (측정, 먼저)

- `settings.firstRecordReturn = { path: 'notify'|'install'|'none', choice: 'accept'|'skip', result: 'granted'|'denied'|'dismissed'|'unsupported'|'', at }`
  - `choice`: 큰 단추를 눌렀는지, "나중에"로 닫았는지.
  - `result`: `ensureAppNotificationPermission` 결과의 `status`.
- 관제탑 「🌱 성장」에 한 줄: **"첫 기록 뒤 알림 받기 — 본 사람 / 누른 사람 / 허락된 사람, 그리고 각각의 둘째 날 기록률"**.
- 손대는 곳: `runFirstRecordNextStep`, `finishFirstRecordResult`, `enableFirstRecordReminder`, `functions/admin-growth.js`, 테스트 `tests/admin-growth.test.js`.
- 개인 정보: 고른 단추와 결과만. 시각은 서버 시각.

### 4-1. 기록이 1번인 회원에게 식단 탭 맨 위 상자 (둘째 기록 권유)

- 지금 0번 회원에게 쓰는 빨간 상자 자리를 1번 회원에게도 쓴다. 문구만 다르다.
  - 제목: **"오늘 한 장이면 이틀째예요"**
  - 설명: "어제처럼 지금 눈앞의 것 한 장이면 돼요."
  - 단추: 📸 지금 찍기 (0번 회원 상자와 같은 동작)
- **오늘 이미 기록했으면 숨긴다.** 첫 기록 당일에는 보이지 않는다. 둘째 기록을 하면 사라진다.
- 알림이 연결되지 않은 플레이 앱 회원에게는 상자 아래 작은 줄 하나: "내일부터 이 시간에 알려 드릴까요? **알림 받기**" → `enableFirstRecordReminder(지금 시각)`.
  결과 창에서 놓친 사람에게 **실제로 다시 앱을 연 순간** 한 번 더 묻는다. 한 번 "나중에"를 누르면 그 회원에게는 다시 묻지 않는다.
- 손대는 곳: `_firstRecordNudgeUid` 를 정하는 곳(`hasStartedRecording` 대신 기록일 수), `index.html` 상자, `js/i18n-ko.js`·`js/i18n-en.js`.

### 4-2. 하루 빠진 다음 날 메일: 기록이 1번인 회원에게는 다른 문구

- 같은 메일(공백 2일)이 첫 기록 하나만 남긴 새 회원에게도 간다. 지금 문구는 "다시 돌아와 주세요"에 가깝다.
- 기록일이 1일인 회원에게만:
  - 제목: "[해빛스쿨] ○○님, 첫 기록 다음 한 장 🌞"
  - 본문 요지: 첫 기록을 남기셨어요 → 두 번째는 더 쉬워요, 지금 눈앞의 것 한 장 → 기록하기 단추.
- 보내는 시점, 대상, 중복 방지 장부(`reEngagementByDays.day3`)는 그대로. 문구만 고른다.
- 손대는 곳: `functions/reengagement-email.js` (`buildReEngagementEmailTemplate` 에 `firstTimer` 같은 표시), `runScheduledReEngagementSweep` 에서 기록일 수 계산, 테스트.
- 대표님 말투 기준: 공포 표현 없이, "~만" 대신 "~면 돼요".

### 4-3. 첫 기록 결과 창 알림 질문을 "내일"로 분명하게

- 지금: "다음 끼니 때 알려 드릴까요? ○시에 아직 기록이 없으면 **한 번** 알려 드려요."
  실제로는 매일 같은 시각에 켜진다(`reminderPreference.enabled = true`). "한 번"은 사실과 다르고, 매일인 줄 알면 허락을 망설일 수 있다.
- 바꿀 문구:
  - 제목: "내일도 이어 갈 수 있게 알려 드릴까요?"
  - 설명: "매일 ○시에 그날 기록이 없을 때만 한 번 알려 드려요."
- 손대는 곳: `renderFirstRecordReturn` 의 notify 칸 문구(한·영).
- 주의: 습관 알림(`reminderPreference`)만 따로 끄는 화면은 7월에 빠졌다(`js/app-core.js` 주석). 지금 끄는 길은 내 정보의 기기 푸시 끄기뿐이라
  "언제든 끌 수 있어요" 를 넣으려면 끄는 줄을 먼저 되살려야 한다. 넣을지는 대표님 결정.

## 5. 하지 않는 것

- **새 포인트 보상 만들기** (예: 3일 연속 보너스). 포인트 경제에 닿는 일이라 대표님 결정이 따로 필요하다. 이 설계는 보상 없이 묻는 때와 문구만 바꾼다.
- 알림 횟수 늘리기. 하루 한 통 그대로.
- 웹(설치 안 한 브라우저)에 알림 권하기. 설치 권유 그대로.
- 첫 기록 안내 메일(7%) 손보기. 이번 범위 밖이다.
