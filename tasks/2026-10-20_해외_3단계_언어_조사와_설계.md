## 1. 영어 앱에서 보상(해빛 배지·투표)을 어떻게 보여 줄까 — 가장 급함

### 1-1. 코드로 확인한 지금 상태

- 영어 앱(`/en`)은 **"심플 모드"** 로 돈다(`js/app-mode.js` `getRouteContext`: 영어면 `mode = 'simple'`).
  심플 모드가 쓸 수 있는 탭은 `diet·exercise·sleep·profile` 넷뿐이다(`SIMPLE_TABS`).
  → 자산·갤러리·대시보드는 CSS(`styles-en.css` 398~408행)로 숨길 뿐 아니라 **탭 목록에서도 빠져 있다.** 주소로 `#assets` 를 열어도 식단 탭으로 돌아간다.
- 해빛 배지 카드(`js/global-rewards.js`)는 **자산 탭을 그릴 때만** 만들어진다(`updateAssetDisplay` → `loadGlobalRewards`). 영어 앱에서는 이 함수가 아예 불리지 않는다.
- 배지 카드 문구는 이미 영어가 다 있다(`copy(ko, en)` 29곳). 서버(`functions/global-rewards.js`)도 언어와 상관없이 같은 값을 준다.
- 영어 앱에는 **포인트 잔액이 보이는 곳이 없다.** 머리글 포인트(`#point-badge-ui`)도 숨긴다. 첫 기록 축하 화면에서 한 번 보일 뿐이다.
- 영어 앱 로그인 화면의 약속이 맞지 않는다: `login.point2` = "☕ Record to earn points and get a coffee".
  영어 앱 회원은 커피 쿠폰(기프티쇼)을 볼 수도, 바꿀 수도 없다.
- 영어 앱 프로필은 따로 만든 작은 화면(`#english-profile-shell`: 계정·언어·알림·로그아웃)이다. 나머지 프로필 카드는 전부 숨긴다.
- 대표 배지 안내 문구(영어)가 "갤러리와 카카오톡 단톡방 순위에서 이름 앞에 보여요" 인데, 영어 회원은 둘 다 볼 수 없다.
  (영어 회원의 식단·운동·수면 글은 한국어 갤러리에 공개되므로, **한국 회원 눈에는** 배지가 보인다.)

### 1-2. 선택지

| | 안 | 한국어 앱 영향 | 일의 양 | 좋은 점 / 나쁜 점 |
|---|---|---|---|---|
| **A (추천)** | 영어 프로필 화면에 **"Rewards" 카드 하나**를 넣는다: 내 포인트 · 🏅 해빛 배지 6개(사기·대표로 달기) · 해외 시간대 회원만 기프트카드 투표 | 없음(영어 프로필 화면 안에서만 그린다) | 작음 | 탭을 새로 열지 않아 HBT·지갑·챌린지·기프티쇼를 하나씩 숨길 필요가 없다. 플레이 잠금과 부딪힐 일이 없다. / 자산 탭만큼 자세하지 않다(포인트 내역 없음) |
| B | 영어 앱에 **자산 탭을 연다**(탭 5개). HBT·지갑·전환·챌린지 예치·기프티쇼는 영어에서 숨긴다 | 탭 목록·자산 탭 코드를 같이 건드림 | 큼 | 포인트 그래프·내역까지 보인다. / 숨길 것이 많고, 하나라도 새면 플레이 정책(HBT) 문제. 자산 탭 문구 대부분이 한국어라 번역도 많다 |
| C | 지금은 안 연다 | 없음 | 없음 | 해외 회원이 포인트를 쓸 곳이 계속 없다 |

**추천: A.** 영어 회원에게 필요한 것은 "포인트가 얼마 있고, 어디에 쓰는가" 뿐이다. 자산 탭의 나머지는 한국 전용이다.

A 를 고르면 함께 할 것:
1. `loadGlobalRewards` 가 카드를 놓을 자리를 받게 한다(자산 탭 / 영어 프로필). 그리는 코드는 그대로 쓴다.
2. 영어 프로필 탭을 열 때 부른다. 접힌 상태 기본값: 영어에서는 **펼쳐서** 보여 준다.
3. 영어 문구 고치기 — 로그인 화면 `login.point2`·`invite.point2` 의 "get a coffee" → 배지·포인트 문구로(대표 문구 확인).
   대표 배지 안내(영어)에서 "KakaoTalk group ranking" 을 뺀다.
4. 기프티쇼(한국 매장 쿠폰)는 영어 앱에서 **보이지 않는다**(지금과 같음). 서울 시간대 영어 회원(한국에 사는 외국인)에게도
   열지는 질문 1-2 로 묻는다. 상품 이름·안내가 전부 한국어이고 한국 휴대폰 번호가 있어야 받는다.

## 2. 플레이 앱을 해외에서 깔았을 때 첫 화면 언어

### 2-1. 코드로 확인한 지금 상태

- 안드로이드 앱(TWA)은 `https://habitschool.web.app/app` 을 연다(`AndroidManifest.xml` `DEFAULT_URL`). 바꾸려면 AAB 를 새로 올려야 한다.
- `/app` 은 `index.html` 을 그대로 쓰고(호스팅 rewrite), 언어는 **주소만** 보고 정한다. `navigator.language` 를 읽는 곳이 없다.
- 플레이 잠금(HBT 숨김)은 `index.html` 머리(head)의 동기 스크립트가 첫 화면 전에 정한다: `/app` 이거나, TWA 에서 왔거나(`android-app://` referrer),
  이미 표시가 있으면(`sessionStorage.hs_play_context = '1'`) `html.play-mode`. 표시는 같은 앱 세션에서 `/`·`/simple`·`/en` 으로 옮겨도 남는다.
- 로그인 화면 아래에 이미 버전 고르기(기본형·심플·English·라이트)가 있다. 그러나 한국어 화면이고 작은 버튼이라 외국인이 찾기 어렵다.
  영어 화면에서는 "Full / Simple / English / Lite" 로 보이는데, **"Full" 이 한국어라는 뜻인지 알 수 없다.**
- **추가로 찾은 것:** 안드로이드 앱의 공유·위젯·헬스커넥트 진입(`AppRoutes.kt`)과 서비스워커의 공유 받기(`sw.js` 244행)는 모두 **`/`(한국어)** 로 연다.
  영어 화면으로 옮겨 준다 해도, 사진을 공유하면 다시 한국어 화면이 뜬다.
- 앱 안의 글자 일부(앱 이름 "해빛스쿨", 헬스커넥트 안내 창, 위젯 글자)는 안드로이드 쪽 `res/values/strings.xml` 에만 있어 한국어다.
  이것은 웹으로 못 바꾼다 → 다음 AAB 를 올릴 때 `values-en/strings.xml` 을 같이 넣는다(이번 단계 밖, 따로 기록).

### 2-2. 방법 (AAB 재업로드 없이)

`index.html` 머리 스크립트에서, 플레이 잠금 판정 **바로 뒤에** 아래를 한다.

```
조건: 지금 주소가 /app 이고
      (a) 이 기기에 저장된 언어 선택이 'en' 이거나
      (b) 저장된 선택이 없고 + 이 기기에서 로그인한 표시(habitschool-signed-in-hint-v1)가 없고
          + 기기 언어(navigator.languages 첫 값)가 'ko' 로 시작하지 않으면
동작: location.replace('/en' + 원래의 ?검색 + #해시)
```

- 플레이 잠금 표시(`hs_play_context`)는 같은 스크립트가 **옮기기 전에** 이미 적는다. 옮겨 간 `/en` 에서는 referrer 가 TWA 가 아니게 되지만
  표시가 남아 있어 잠금이 유지된다. `/en` 은 원래 HBT 를 보여 주는 탭이 없어 이중으로 안전하다.
- `replace` 라 뒤로 가기에 `/app` 이 남지 않는다. 같은 주소(origin) 안의 이동이라 TWA 주소창도 생기지 않는다.
- 첫 화면이 그려지기 전(모듈을 받기 전)에 옮기므로 한국어 화면이 비쳤다가 바뀌지 않는다.
- **언어 선택 저장:** 로그인 화면·프로필에서 언어(버전)를 고르면 `localStorage` 에 `'ko'`/`'en'` 을 적는다(`switchAppVersion`, `switchHabitSchoolLocale`).
  한 번 "한국어" 를 고른 사람은 다시는 영어로 옮기지 않는다.
- **이미 쓰던 한국 회원 보호:** 로그인했던 표시가 있으면 자동으로 옮기지 않는다. 기기 언어가 영어인 해외 한인 회원이 업데이트 뒤 갑자기
  영어 화면을 보는 일을 막는다. (주의: 이 표시는 v523(커밋 89db9cf3, 2026-10-20)부터 적는다. 그 버전 전에 로그인하고 그 뒤로 한 번도 안 연 회원은 표시가 없다.
  운영 집계상 앱을 여는 회원은 35명이고 모두 한국어 기기일 가능성이 크지만, 확인 방법은 3-4절 테스트로 묶는다.)
- **공유·위젯 진입:** 플레이 앱 세션이고 저장된 선택이 `'en'` 이면 `/` 로 들어와도 `/en` 으로 같은 방식으로 옮긴다(검색·해시 그대로).
  구현 때 영어 앱이 `focus=shared-upload`·`sharedUploads`·`native=` 를 한국어 앱과 똑같이 처리하는지 먼저 확인한다(아직 확인 안 함).
- **웹(크롬에서 `/`)은 지금처럼 주소가 언어를 정한다.** TWA 와 크롬은 같은 저장소를 쓰므로, 저장된 선택을 웹에도 쓰면 대표가 크롬에서 `/` 를 열 때
  영어로 넘어가는 일이 생긴다. 그래서 자동 이동은 **플레이 앱 세션 안에서만** 한다.
- 영어 로그인 화면의 버전 버튼: "Full" → "한국어" 로 보이게 바꾼다(심플·라이트는 한국어 화면이라 영어 화면에서는 숨기는 것도 검토).

### 2-3. 선택지

| | 안 | 장점 | 단점 |
|---|---|---|---|
| **가 (추천)** | 위 2-2: 기기 언어로 자동, 처음 한 번만, 고르면 기억 | 외국인은 아무것도 안 해도 영어. 한국 회원은 그대로 | 영어 기기를 쓰는 한국인 새 회원은 영어로 시작 → "한국어" 한 번 눌러야 함 |

## 3. 번역 구조 — 지금 모습과 키 기반으로 옮기는 단계

### 3-1. 지금 번역은 다섯 가지 방법이 섞여 있다 (2026-10-20 센 값)

| # | 방법 | 위치 | 개수 |
|---|---|---|---|
| ① | HTML 에 한국어를 쓰고 `data-i18n="키"` 를 단다 → 영어일 때 사전에서 바꿔 끼운다 | `index.html` | `data-i18n` 98 · `-html` 13 · `-placeholder` 2 · `-aria-label` 7 |
| ② | 선택자 → 영어 문장 (키 없음) | `js/i18n.js` `SELECTOR_TEXTS`·`_ALL`·`_ATTRS` | 67 · 6 · 40 |
| ③ | 한국어 문장 → 영어 문장 바꿔치기, 화면 변화를 감시하며 계속(`MutationObserver`) | `ENGLISH_TEXT_REPLACEMENTS` | 30 쌍 (식단·운동·마음·프로필·저장 바 안에서만) |
| ④ | 코드 안 갈림길 `isEnglishLocale() ? … : '한국어'` | `app-core.js` 286 · `auth.js` 53 · `diet-analysis.js` 10 · `global-rewards.js` 3(+`copy()` 29) | 그중 영어 쪽이 `t('키')` 인 것 40, 나머지 약 310 은 영어 문장이 코드에 그대로 |
| ⑤ | 영어 전용 화면을 따로 만들고 한국어 화면은 CSS 로 숨김 | `#english-profile-shell`, `#english-public-page`, `styles-en.css` | — |

- 사전(`MESSAGES`)은 **영어 296 키, 한국어 27 키**다. 한국어 문장 대부분은 HTML·코드 안에 있고, 사전에는 영어만 있다.
  → `t()` 를 한국어로 부르면 사전에 없는 키는 **키 이름이 그대로** 나온다. 그래서 지금 코드는 늘 `isEnglishLocale() ? t() : '한국어'` 로 감싼다.
- 영어 문장은 모두 합쳐 약 **600개**. 세 번째 언어를 넣으려면 ②·③·④ 의 약 450개는 키가 없어 손댈 곳이 없다.
- 영어 화면에 실제로 나오는 곳은 식단·운동·마음·영어 프로필·로그인/동의/온보딩·토스트뿐이다. 대시보드·자산·갤러리·관제탑(한국어 `app-core.js` 줄의 대부분)은
  영어 앱에 안 나오므로 **옮길 필요가 없다.**
- 서버 쪽: AI 분석 프롬프트(식단·수면·걸음 캡처)와 다시 오세요 메일·푸시는 이미 `locale` 로 갈린다(`functions/runtime.js`, `reengagement-email.js`).

### 3-2. 목표 모양

- 언어마다 사전 파일 하나: `js/i18n/ko.js`, `js/i18n/en.js` (나중에 `ja.js`). 키 모양은 `화면.요소` (예: `diet.saveButton`).
- `t(키)` 순서: 지금 언어 → (한국어가 아니면) 영어 → 한국어. 세 번째 언어에 빠진 키가 있으면 한국어가 아니라 영어가 나온다.
- HTML 은 지금처럼 **한국어를 그대로 쓰고** `data-i18n` 만 단다. 한국어 화면은 사전 없이 첫 화면이 그려진다(지금과 같은 속도·모양).
  한국어 사전의 그 키 값은 HTML 문장과 **똑같아야** 한다 — 테스트로 묶는다.
- 코드는 `isEnglishLocale() ? 'A' : '한'` → `t('키')` 로, `'한'` 은 한국어 사전으로 옮긴다. 글자는 하나도 바꾸지 않는다.
- ②·③ 은 화면을 옮길 때마다 그 화면 몫을 지운다. 마지막에 둘 다 0개가 되면 `MutationObserver` 바꿔치기도 지운다.

### 3-3. 화면 단위 단계 (한 번에 한 화면, 한 화면 = 커밋 하나 = 스테이징 확인 한 번)

| 단계 | 화면 | 대략 양 | 비고 |
|---|---|---|---|
| L0 | 바탕: 사전 파일 나누기, `t()` 순서, 테스트(3-4) | 코드 작음 | **화면 변화 0.** 지금 사전을 그대로 옮기기만 |
| L1 | 영어 프로필 + 새 Rewards 카드(1번 A) | 새로 만드는 것이라 처음부터 키로 | 1번 구현과 같이 |
| L2 | 로그인·동의·온보딩·첫 기록 축하 (`auth.js` 53곳, `login.*`·`consent.*`) | 중 | 2번(첫 화면)과 같이 보면 좋다 |
| L3 | 식단 탭 (+`diet-analysis.js`, 바꿔치기 ③ 대부분) | 중 | |
| L4 | 운동 탭 | 중 | |
| L5 | 마음 탭(수면·명상·감사) — `meditation-guide.js` 는 자기만의 언어 판정이 따로 있다 → 같은 `getLocale()` 로 | 중 | |
| L6 | 공통: 토스트·오류 제보·저장 바·날짜/시간대 배지 | 중 | 끝나면 ②·③ 0개 → 바꿔치기 장치 삭제 |
| L7 | (열기로 하면) 갤러리 | 큼 | 4번 결정 뒤 |

- 한국어 전용 화면(대시보드·자산의 HBT/기프티쇼·관제탑)은 **옮기지 않는다.** 일본어 계획이 생기면 그때 L7 뒤에 붙인다.

### 3-4. "한국어 앱은 하나도 안 바뀐다" 를 증명하는 테스트 — 구현 첫 커밋에 먼저 넣는다

`tests/korean-app-unchanged-i18n.test.js` (가칭). 기준 파일(fixtures)은 **지금 main 에서 한 번 만들어 커밋**하고, 그 뒤 고치는 커밋들은 이 기준과 비교한다.

1. **HTML 한국어 그대로:** `index.html` 의 보이는 글자(텍스트 노드)와 한국어 속성값(`aria-label`·`placeholder`·`title`·`alt`)을 순서대로 뽑아
   기준 파일과 같아야 한다. `data-i18n` 같은 속성을 더하는 것은 괜찮고, 글자가 하나라도 바뀌면 실패.
2. **코드 속 한국어 문장 그대로:** `js/*.js` 의 한글이 든 문자열 + 한국어 사전 값을 모은 집합이 기준 집합을 **빠짐없이** 포함해야 한다.
   문장을 사전으로 옮기면 통과, 고치거나 지우면 실패.
3. **옮긴 키는 옛 문장과 같다:** 화면마다 "키 → 옮기기 전 한국어" 표를 테스트에 적고, 한국어로 `t(키)` 가 그 문장을 돌려주는지 본다.
4. **주소·탭 그대로:** `/`·`/simple`·`/app`·`/welcome` 의 `getRouteContext` 결과와 탭 목록이 지금과 같다.
5. **첫 화면 이동 스크립트:** 머리 스크립트를 가짜 `location`·`navigator`·저장소로 돌려 본다.
   한국어 기기 / 로그인 표시 있음 / 저장된 선택 'ko' / `/app` 이 아닌 주소 / 일반 크롬(플레이 세션 아님) → **이동 없음**.
   외국어 기기 + `/app` + 처음 → `/en?…#…` 로 이동, 그리고 이동 전에 `hs_play_context = '1'` 이 적혀 있음.
6. **플레이 잠금:** `/en` + 플레이 표시 → `html.play-mode`, 그리고 영어 Rewards 카드에 HBT·지갑 요소가 없음.
7. **새 CSS 는 영어에만:** 새로 넣는 규칙이 전부 `html.locale-en` 으로 시작한다.
8. **사전 짝 맞춤:** 한국어 사전의 키는 영어 사전에 다 있다. 영어 값에 한글이 없다(언어 이름 "한국어" 같은 허용 목록 제외).

기존 테스트(`play-mode`, `english-locale`, `english-entry`, `korean-text-integrity`, `global-rewards-korea-unchanged`)는 그대로 통과해야 한다.

## 4. 커뮤니티(갤러리·댓글)를 언어별로 나눌까

### 4-1. 지금

### 7-4. 번역을 어떻게 넣나 — 한국어 화면은 건드리지 않는 방식

- **HTML: 빌드할 때 영어판을 만든다.** `scripts/generate-en-entry.js` 가 이미 `index.html` → `en/index.html` 을 만든다(지금은 제목·메타만 바꿈).
  여기에 "`data-i18n` 이 달린 요소의 글자를 영어 사전 값으로 바꿔 쓰기" 를 더한다.
  - 한국어 `index.html` 은 글자가 그대로다(속성만 늘어남). 한국어 첫 화면은 지금과 똑같다.
  - 영어 첫 화면은 처음부터 영어로 온다 → 지금처럼 화면을 숨겼다가(`locale-loading`) 바꿔 끼우는 깜빡임·지연이 없어진다.
  - 세 번째 언어는 `ja/index.html` 을 같은 스크립트로 만든다.
  - 빌드 확인(`npm run check:en`)이 "사전에 없는 키", "한글이 남은 영어 HTML" 을 잡게 한다.
- **JS: `t('키')`.** 한국어 문장은 `js/i18n/ko.js` 로 글자 그대로 옮기고, 영어는 `js/i18n/en.js`.
  `isEnglishLocale() ? 'A' : '한'` 갈림길은 옮길 때마다 없앤다.
- **바꿔치기 장치(선택자 표·문장 표·화면 감시)** 는 탭을 옮길 때마다 그 몫을 지우고, 다 옮기면 장치째 지운다.
- **날짜·숫자:** `formatDate` 처럼 `Intl` 을 쓰는 곳은 언어만 넘기면 된다. "3일 연속", "10월 20일", "1,000P" 처럼
  글자를 붙여 만든 곳은 키에 자리표시(`{days}`)를 넣어 옮긴다. 한국어 조사(`js/korean.js`)는 한국어에서만 쓴다.
- **서버 문구:** 푸시 제목·본문과 회원에게 보이는 오류 문구는 회원 `locale` 로 고른다(다시 오세요 메일이 이미 이렇게 한다).

### 10-2. 자동 번역 방식 (대표 결정 8 "기기 언어로 자동 번역")

- 원문은 그대로 두고, 글 옆에 언어별 번역을 붙인다: `translations: { en: {…같은 모양의 글 칸만…}, ko: {…} }`, `sourceLocale`, `sourceHash`.
- 화면은 보는 사람 언어 번역이 있으면 그것을, 없으면 원문을 보여 준다. "원문 보기" 를 둔다.
- Gemini gemini-2.5-flash, thinkingBudget 0, 글 하나의 칸을 한 번에 JSON 으로 번역. 원문이 바뀐 때만 다시 번역(sourceHash).
- 언제 번역하나 — 대표 확인:
  - (가) 처음 보는 사람이 있을 때 한 번 번역해 저장(나중 번역). 영어 회원이 적은 지금은 비용이 거의 없다. 처음 보는 사람은 원문이 잠깐 보였다가 바뀐다.
  - (나) 저장할 때 모든 글을 미리 번역(설계 8절 처음 안). 늘 바로 보이지만, 한국어 글 대부분은 영어로 볼 사람이 없어 비용이 낭비된다.
