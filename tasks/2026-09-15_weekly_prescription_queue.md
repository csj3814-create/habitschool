# 주간 다이렉트 처방 대기열

## 결정된 것 (2026-09-15)

> "7일에 한번정도로 다이렉트 처방 중에서 가장 의미있는 정보부터 해서 자동으로 발송하도록 하면 어때?"

**자동 발송 전에 대기열을 한 단계 둔다.** 크론이 주 1회 전원 초안 재료를 모아
점수순으로 쌓고, 원장님이 목록에서 클릭 한 번으로 보내거나 고쳐 보낸다.

이유: 지금 초안 순서는 중요도가 아니라 **종류**(경보→나빠짐→좋아짐→꾸준함→
빈자리→복귀)다. 걸음수가 100보 늘어난 사람과 3,000보 늘어난 사람이 같은 순위를
받는다. "가장 의미있는 정보부터" 를 하려면 실제 점수가 먼저 필요하고, 그건
자동이든 수동이든 어차피 해야 하는 일이다.

그리고 대기열은 **자동화해도 되는지 판단할 데이터를 만든다.** 그대로 보낸 비율이
높으면 자동 발송이 정당화되고, 절반을 고치셨다면 자동은 그만큼 잘못된 메시지를
보냈을 거라는 뜻이다. 운동 강도 신호 때와 같은 방식이다(2026-09-15 기준선 참조).

### 제외 대상 (사용자 선택)

| 제외 | 이유 |
|---|---|
| 경보 (혈당·혈압 기준 초과) | 사람이 보고 보낸다. 대기열에는 올리되 **자동 발송 대상 아님** 표시 |
| 같은 종류 4주 내 재발송 | 3주 연속 '걸음수 칭찬'이 가면 자동이라는 게 드러난다 |
| 최근 14일 기록 없는 회원 | 이탈 회원 복귀는 기존 재참여 메일이 이미 담당한다 |
| 회원이 끈 경우 | 프로필에 코치 메시지 수신 스위치를 둔다 |

## 구조 판단 — 문장은 한 곳에서만 만든다

`buildAdminPrescriptionDrafts` 는 `js/admin-utils.js` 에 있다. `functions/` 는
`js/` 를 참조하지 않고(확인함), hosting 은 `functions/**` 를 무시한다. 서버에서
문장까지 만들려면 로직이 두 벌이 된다 — `reward-market.js` 가 이미 양쪽에 있는
전례가 있지만, **방금 문구를 고친 기능에서 사본을 만드는 건 같은 실수를 예약하는
일이다.**

그래서:

- **크론은 비싼 데이터만 모은다.** 회원당 4번 읽어야 하는 추이(`loadMemberHealthTrends`)와
  30일 로그가 그 부분이다.
- **문장과 순위는 관제탑이 만든다.** 지금과 같은 코드, 같은 한 벌.
- 크론이 저장하는 로그는 `buildAdminPrescriptionDrafts` 가 **실제로 읽는 필드만**
  추린 슬림 사본이다. 함수를 고칠 필요가 없고 문서도 작다(30일 × ~200B).
- 발송은 기존 `submitAdminFeedback` 을 그대로 쓴다. 새 발송 경로를 만들지 않는다.

## 작업 순서

### 1. 의미 점수 (`js/admin-utils.js`) — 단독으로도 값어치가 있다

지금 모달의 초안 순서도 같이 좋아진다. 대기열과 무관하게 먼저 넣는다.

- 초안마다 `score`(0~100)와 `requiresHuman` 을 단다.
- 점수순 정렬. 같은 점수면 기존 종류 순서를 유지한다.
- **하한선**을 둔다. 하한 미만이면 아예 만들지 않는다 — 보낼 말이 없으면
  보내지 않는 게 맞다. 빈 초안 문구가 이미 그렇게 말하고 있다.

### 2. 크론 + 대기열 (`functions/runtime.js`, `firestore.rules`)

- `buildWeeklyPrescriptionQueue` onSchedule (월 09:00 KST)
- 대상: 최근 14일 기록이 있고 수신을 끄지 않은 회원
- 회원당: 슬림 로그 30일 + 추이 요약 + 스트릭 + 최근 4주 발송 이력
- `prescription_queue/{uid}` 에 저장. **관리자 전용 규칙 → 별도 배포 승인 필요**

### 3. 관제탑 대기열 화면 (`admin.html`)

- 새 탭. 점수순 목록, 회원명·요약·근거·점수·경보 표시
- 클릭 → 그 회원 상세 모달이 열리고 초안이 채워진 상태 (기존 흐름 재사용)
- "그대로 보내기" 한 번 / 고쳐 보내기 가능
- 보낸 것/건너뛴 것 기록 → 4~6주 뒤 자동화 판단 근거

### 4. 회원 수신 스위치 (`index.html`, `js/`)

프로필에 코치 메시지 수신 스위치. 끄면 대기열에서 빠진다.

## 하지 않는 것

- 자동 발송 — 이번 차수 아님. 대기열 데이터가 쌓인 뒤 결정한다.
- 새 발송 경로 — `submitAdminFeedback` 하나만 쓴다.
- 초안 로직 서버 복사 — 위 "구조 판단" 참조.
