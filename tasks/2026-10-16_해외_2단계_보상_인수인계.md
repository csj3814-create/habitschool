## 대표에게 물을 것 (설계 단계에서)

1. 해외 회원을 무엇으로 가르나 — 시간대, 앱 언어, 회원이 고르는 "사는 나라", 전화번호 국가 중 무엇?
2. 해외 보상을 무엇으로 — 배지·레벨만 / 해외 기프트카드 / 둘 다. 처음에는 몇 나라만?
3. 해외 회원의 포인트 가치 — 1P = 1원 기준을 그대로 달러 환산할지, 해외 상품 가격표를 따로 둘지
4. 해외 회원이 이미 모은 포인트는 그대로 쓰게 할지
5. 비용 한도 — 해외 보상에 한 달 얼마까지 쓸지(충전식이라 미리 돈을 넣어야 한다)

## 지킬 것 (이 프로젝트 규칙 요약 — 원문은 CLAUDE.md)

- 한국 회원의 기프티쇼 교환·한도·가격은 바뀌지 않는다. 테스트로 먼저 묶는다.
- 새 Firestore 필드 → `firestore.rules` 화이트리스트 + **규칙 배포 별도 승인**. 새 비밀키(업체 API 키)는
  Secret Manager 로(`defineSecret`), 코드·저장소에 넣지 않는다.
- 돈이 나가는 API 는 응답 코드만 믿지 않는다(교훈: 기프티쇼가 HTTP 200 안에 오류를 담았다). 발급 결과를 검증하고,
  실패하면 포인트를 돌려준다.
- 화면을 바꾸면 에셋 버전을 올린다(지금 v516). `index.html` 을 바꾸면 `npm run build:en` → `npm run check:en`.
- 테스트는 `npx vitest run` 전부 통과(2026-10-16 기준 2,836개). 워크트리에서는 `node_modules`,
  `functions/node_modules` 를 메인 폴더 것에 junction 으로 연결하고, 끝나면 `cmd /c rmdir` 로 **링크만** 지운다.
- Functions 배포는 hosting 과 따로, 로그를 파일로 남기고 함수마다 `Successful` 줄을 확인한다. `--force` 는 쓰지 않는다.
- 윈도우에서 Python 으로 파일을 고치면 `newline=''` 로 연다(안 그러면 LF 가 CRLF 가 된다). Bash heredoc 안의
  `\\n` 은 `\n` 이 된다. 고친 뒤 `git ls-files --eol` 로 확인.
