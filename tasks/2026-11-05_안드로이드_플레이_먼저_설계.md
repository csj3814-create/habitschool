# 안드로이드 방문자에게 플레이를 먼저 권한다 (설계안)

2026-11-05. 구현 전에 대표 확인을 받는다.

## 한 줄 요약

처음 온 안드로이드 방문자가 보는 소개 페이지에서 **첫 버튼을 「구글 플레이에서 앱 받기」로** 바꾸고, 웹 시작은 그 아래에 둔다.

## 왜

- 10/25 이후 첫 방문 중 안드로이드가 가장 많다: 안드로이드 168명, 아이폰 36명, PC 약 80명(봇 일부 포함).
- 10/25 이후 첫 기록: 플레이 가입자 27명 중 17명, 웹으로만 가입한 13명 중 0명.
  단, 앱을 까는 사람은 원래 의욕이 높을 수 있다. 설치를 권한다고 그만큼 오른다는 증거는 아니어서 재면서 간다.
- 플레이 앱은 걸음수·수면이 자동으로 들어오고, 바탕화면에 아이콘이 생겨 다시 오기 쉽다.

## 지금

- 소개 페이지 버튼은 모든 기기에서 같다: 「구글 계정으로 시작하기」, 「로그인 없이 먼저 둘러보기」, 아래 안내 「설치 안 해도 웹에서 바로 쓰실 수 있고요」.
- 카카오톡 안 브라우저에서는 구글 로그인이 막혀 크롬으로 한 번 더 넘어가야 한다.
- 초대 링크(`/i/코드` → `/?ref=코드`)로 온 사람은 소개 페이지를 보지 않고 로그인 화면으로 간다.

## 바꾸는 것

### 1. 안드로이드 소개 페이지 (맨 위와 맨 아래 버튼 모두)

| 순서 | 지금 | 안드로이드에서 |
|---|---|---|
| 첫 버튼 | 구글 계정으로 시작하기 | **구글 플레이에서 앱 받기** |
| 둘째 버튼 | 로그인 없이 먼저 둘러보기 | **웹에서 바로 시작하기** (`/?start=1`) |
| 작은 글자 링크 | 없음 | 로그인 없이 먼저 둘러보기 |
| 안내 | 돈 드는 거 전혀 없어요. 설치 안 해도 웹에서 바로 쓰실 수 있고요. | 돈 드는 거 전혀 없어요. 앱에서는 걸음수와 수면도 자동으로 들어와요. |

- PWA 버튼은 넣지 않는다. 설치 버튼이 둘이면 헷갈린다. PWA 는 지금처럼 플레이 사용자에게 앱 안에서 권한다.
- 맨 아래 버튼은 플레이 버튼과 「웹에서 바로 시작하기」 둘만 둔다.

### 2. 판단

- `index.html` head 에서 첫 화면 전에 정한다(깜빡임 없음). 소개 페이지이고, 기기가 안드로이드이고, 주소에 `ref` 가 없으면 `ko-android` 를 붙인다.
- 버튼은 두 벌을 HTML 에 두고 CSS 로 하나만 보인다. 스크립트가 안 돌면 지금 버튼이 보인다.
- `/welcome?ref=코드` 도 소개 페이지를 보여 주므로 `ref` 검사가 꼭 필요하다. 플레이로 보내면 코드가 끊긴다.

### 3. 스토어로 보내는 링크

- 일반 브라우저: `https://play.google.com/store/apps/details?id=com.habitschool.app` + 어디서 왔는지 표시(`referrer=utm_source=welcome`).
- 카카오톡 등 앱 안 브라우저: 이미 있는 `intent://…scheme=market…` 방식으로 플레이 앱을 바로 연다. 안 되면 스토어 웹 주소로 간다.

### 4. 재는 것

- 새 이벤트 `landing_store_click` 하나를 승인 목록에 넣는다. 소개 페이지 조회는 `landing_view`, 웹 시작은 `auth_start` 로 이미 센다.
- 11/12 무렵부터 볼 것: 안드로이드 소개 페이지 조회 → 플레이 클릭 / 웹 시작 비율, 플레이·웹 가입 수, 첫 기록까지 간 신규 회원 수.
- 기준값: 10/25~11/5 첫 기록까지 간 신규 회원 17명(플레이 17, 웹 0).
- 방문자가 적어 나눠 시험(A/B)은 하지 않는다. 런비커스 소개 효과도 섞이므로 대략의 방향만 본다.
- **되돌리는 기준:** 3주 뒤 안드로이드 신규 가입과 첫 기록 회원이 함께 줄면 버튼을 되돌린다. HTML 과 CSS 만 바꾸므로 바로 돌릴 수 있다.

## 바꾸지 않는 것

- 아이폰: 지금 버튼 그대로. 사파리에서 홈 화면에 먼저 추가하면 로그인·초대 코드가 이어지지 않을 수 있어, 설치는 기록 뒤에 권한다.
- PC, 영어 앱(`/en`), 플레이 앱 안, 이미 로그인했던 사람, 초대·공유·알림으로 온 사람.
- 로그인 화면. 이번에는 소개 페이지만 바꾼다.
- 배포 범위는 hosting 뿐이다. AAB 와 규칙 변경이 없다.

## 다음 단계 (이번 범위 아님)

초대 링크로 온 안드로이드 방문자에게도 플레이를 권하려면 플레이 설치 정보(Install Referrer)로 코드를 넘겨야 한다.
지금은 스토어 링크에 코드가 없고 앱도 읽지 않아, 그 경로로 가면 초대한 사람의 보상이 끊긴다. 다음 AAB 때 함께 넣는다.

## 시험

- 자동: 안드로이드·아이폰·PC 판단, `ref` 있으면 제외, 이벤트 승인, 맨 위·맨 아래 버튼.
- 브라우저: 모바일 크기에서 안드로이드·아이폰 화면 확인, 첫 화면 깜빡임 없음.
- 사람이 휴대폰으로 한 번 확인: 카카오톡에서 링크 → 플레이 앱이 열리는지. 자동 시험으로 볼 수 없다.
