**가입 → 첫 기록**이 먼저다.

29% → 50% 로만 올려도 활성 기반이 두 배 가까이 된다. 유입을 한 명도

# 2차 판정 — 431명이 멈춘 지점 (2026-09-07)

## 산술로 확정되는 것

`onboardingComplete: true` 를 쓰는 곳은 **딱 두 군데**다.

- `js/app-core.js:24242` — 모달에서 습관을 고른 경우. **`settings.primaryHabit` 을 같이 쓴다**
- `js/app-core.js:24407` — 모달을 띄우지 않고 **자동으로 찍는 경로**

그러므로 `onboardingComplete` 는 있는데 `primaryHabit` 이 없는 사람은 전부 24407 을 지났다.

| | `onboardingComplete` | `primaryHabit` | 자동으로 찍힌 인원 |
|---|---:|---:|---:|
| 기록 0명 (431) | 352 | 86 | **266** |
| 기록 있는 사람 (177) | 168 | 44 | **124** |
| **합계 (608)** | **520** | **130** | **390 (64.1%)** |

**608명 중 390명(64.1%)이 온보딩 모달을 한 번도 보지 못한 채 "완료"로 찍혔다.**
추론이 아니라 두 필드의 뺄셈이다.

## 그래서 431명은 어디서 멈췄나

| 여기까지 가고 멈춤 | 인원 | 비중 |
|---|---:|---:|
| 아무 표식 없음 — 로그인 자체가 안 끝남 | 11 | 2.6% |
| **로그인 부트스트랩만 (`referralCode`/웰컴 200P)** | **311** | **72.2%** |
| 온보딩에서 습관 선택 | 60 | 13.9% |
| 주간 미션 선택 | 40 | 9.3% |
| 기본 정보 입력 | 9 | 2.1% |

**로그인은 성공했다.** 311명은 초대 코드를 발급받고 200P까지 받았다. 그리고
거기서 끝났다. 로그인 실패로 잃은 사람은 11명(2.6%)뿐이다.

즉 **"가입 문턱이 높다" 가 아니라 "가입 직후 아무 일도 일어나지 않는다"** 다.

## 왜 그렇게 되나 — 게이트가 뒤집혀 있다

`js/app-core.js:24376` 이 온보딩 표시보다 **먼저** 있고 조건 없이 빠져나간다.

```js
if (userData.welcomeBonusGiven) {
    clearPendingSignupOnboardingState();
    if (modal) modal.style.display = 'none';
    return;                     // ← isPendingSignup 검사에 닿지 못한다
}
if (isPendingSignup) { /* 모달 표시 */ }
```

그리고 모달을 띄울지는 `shouldShowSignupOnboarding()`
(`js/auth-login-helpers.js:127`)이 정하는데, 그 근거가 **sessionStorage 에 담긴
30분짜리 표식**이다 (`js/auth.js:183`, `PENDING_SIGNUP_ONBOARDING_MAX_AGE_MS`).

닫히는 순서:

1. 가입 → sessionStorage 에 표식
2. 표식이 사라지면(리다이렉트 로그인·탭 종료·30분 경과) `shouldShowSignupOnboarding` 이 false
3. → 24404 의 `!hasPendingSignupOnboarding` 가 참 → **`onboardingComplete: true` 자동 기입**
4. 다음 접속에서 `shouldAutoGrantWelcomeBonus`(= `onboardingComplete && !welcomeBonusGiven`)
   가 참 → 200P 지급
5. 이제 `welcomeBonusGiven` 이 참 → **24376 이 영구히 모달을 막는다**

**한 번 놓치면 되돌아올 길이 없다.** 표식은 sessionStorage 라 리다이렉트 로그인
(삼성 인터넷·카카오 인앱 브라우저 — 이 저장소가 4~5월 내내 씨름한 그 경로)에서
특히 잃기 쉽다.

## 같이 죽는 것 — 첫 기록 축하 모달

`settings.firstRewardPending: true` 도 24245, 즉 **온보딩 완료 핸들러에서만** 쓰인다.
그런데 첫 기록 결과 모달은 이 값을 게이트로 쓴다 (`js/app-core.js:24156`):

```js
if (userData?.settings?.firstRewardPending !== true) { ... return false; }
```

**온보딩을 건너뛴 사람은 나중에 기록을 해도 첫 보상 화면을 못 본다.** 200P 선물도,
2,000P 쿠폰까지 남은 거리도 안 보인다. 활성화 장치 두 개가 같은 누락으로 함께 꺼진다.

## 이건 이번 주에 이미 적은 패턴이다

`tasks/lessons.md` 2026-09-06:

> **"한 번만 참인 조건"으로 요청을 걸지 않는다.** … 변화가 아니라 **불일치를 조건으로
> 삼는다** … 로 바꾸면 스스로 낫는다.

온보딩 게이트가 정확히 같은 모양이다. 조건이 **"방금 가입했다는 휘발성 표식이 있나"**
인데, 있어야 할 조건은 **"이 회원이 습관을 고른 적이 있나"** (`settings.primaryHabit`)
— 서버 문서에 남는 값이고, 어긋나 있으면 다음 접속에서 저절로 회복된다.

## 수리 방향 (아직 손대지 않음)

1. `welcomeBonusGiven` 을 온보딩 게이트에서 뺀다. 24376 은 보너스 중복지급을 막는
   조건이지 온보딩을 막을 이유가 없다
2. 온보딩 표시 조건을 sessionStorage 표식 → **`settings.primaryHabit` 부재**로 바꾼다
3. `firstRewardPending` 을 온보딩 핸들러가 아니라 **가입 시점(서버)** 에 심는다

셋 다 인증·온보딩 임계 경로다. **431명 중 311명이 걸린 자리이므로 값이 크지만,
잘못 건드리면 로그인이 깨진다.** 스테이징에서 신규 계정으로 리다이렉트 로그인까지
재현해 확인한 뒤에 올린다.
