# 병원 시범 운영 — 병원 QR 연결 (2026-11-17) · 승인 2026-11-17, **스테이징 배포 완료**. 운영 배포·운영 규칙 배포는 대표 신호 대기

요셉의원(고영초 원장)·내과의사 사이먼(오기창 원장) 12주 시범. 병원이 하는 일은 QR 카드 건네기와
진료 때 환자 휴대폰 화면 30초 보기뿐이다. 새 서버·새 DB 없이 지금 앱과 지금 Firebase 프로젝트에 넣는다.

## 지키는 선 (원장님께 한 약속)

- 병원은 환자 정보를 넘겨받지 않는다 — 병원용 화면·대시보드·내보내기 없음. `clinics` 문서는 공개 정보만,
  회원 문서는 지금처럼 본인과 관리자만 읽는다.
- 포인트는 기록 행동에만. 병원 연결·내원과 묶인 포인트·HBT·미션·알림은 만들지 않는다.
- 진단·처방·약 조절 안내 없음. 띠에는 병원 이름·원장 이름·인사말만 나온다.

## 먼저 확인한 것

- 초대 링크(`?ref=`)가 이미 같은 일을 한다: 페이지를 열 때 localStorage 에 적어 두고(구글 로그인으로 페이지가
  바뀌어도 남음), 로그인 뒤 `js/auth.js` 의 회원 문서 저장 바로 다음에 처리한다. 병원 링크도 이 길을 그대로 탄다.
  새 라우터는 만들지 않는다.
- **`/app` 은 플레이 앱 경로다.** 브라우저에서 열어도 이 탭(세션) 동안 HBT·지갑이 숨는다(`play-mode`).
  병원 환자에게는 오히려 맞다 — 암호화폐 화면이 안 보인다. 플레이 앱이 깔린 휴대폰은 앱으로 열린다.
  처리는 주소와 무관하게 `?clinic=` 만 보므로 `/?clinic=` 도 똑같이 된다.
  → **QR 주소: `https://habitschool.web.app/app?clinic=joseph`, `.../app?clinic=simon`**
- `/` 에 붙어도 `?clinic=` 이 있으면 소개 페이지 대신 로그인 화면이 바로 뜬다(머리 스크립트의 "할 일이 있어 온 주소").
- 회원 문서 쓰기는 `firestore.rules` 화이트리스트(`isAllowedUserField`·`isAllowedUserCreate`)에 없으면 조용히 거부된다
  (2026-08 동의 기록 사고). 새 필드는 규칙 + 배포 + 첫 저장 뒤 실제로 들어갔는지 확인.
