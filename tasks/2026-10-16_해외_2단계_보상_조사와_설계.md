## 1. 지금 보상 구조 (코드로 확인한 것)

### 1-1. 포인트를 버는 쪽

- 기록 포인트는 하루 최대 **80P** — 식단 30 · 운동 30 · 마음 20 (`functions/points-utils.js:15` `DAILY_POINT_CAPS`).
  그 밖에 마일스톤·챌린지·소모임 100회(2,000P) 같은 보너스가 있다.
- 1단계 이후 하루 경계는 회원 시간대 기준이다. 해외 회원도 포인트는 똑같이 쌓인다.

### 1-2. 포인트를 쓰는 쪽 — 기프티쇼 (`functions/reward-market.js`, 4,525줄)

| 항목 | 지금 값 | 코드 위치 |
|---|---|---|
| 가격 | **1P = 1원.** 2,000원 쿠폰 = 2,000P. 회사가 내는 돈은 1,880원(매입가) | `DEFAULT_REWARD_CATALOG` (60행~) |
| 최소 교환 | 500P | `REWARD_MARKET_MIN_REDEMPTION_POINTS` |
| 첫 교환 할인 | 평생 한 번 1,400P | `DEFAULT_FIRST_REDEMPTION_POINT_COST`, `resolveFirstRedemptionDiscountForMember` |

| 받는 곳 | 앱 쿠폰 보관함(`app_vault`). 기프티쇼 주문에는 번호가 꼭 들어간다(`phone_no`) | 306행 |
| 한도 | 일·주·월 한도 | `buildLimitSummary` 1825행 |

**인수인계 문서와 다른 점 하나 — 교환 한도는 회원 한 명의 한도가 아니라 서비스 전체 합계다.**
`loadIssuanceUsage`(1776행)는 `reward_redemptions` 를 **회원 구분 없이** 이번 달 것 전부 읽어 더한다.
즉 "하루 2,000P" 는 "그날 모든 회원이 바꾼 합이 2,000P" 라는 뜻이다(코드 기본값. 운영 값은 `functions/.env` 에 있고
예시 파일은 하루 20,000P · 주 100,000P · 월 300,000P). 회원 한 명에게 걸린 제한은 "첫 교환 할인 1회" 와
"처리 중인 같은 상품 재주문 막기" 뿐이다.

→ **설계에서 중요한 이유:** 해외 교환을 `reward_redemptions` 에 같이 쌓으면 한국 회원이 쓸 한도를 해외 교환이 깎아 먹는다.
해외 교환은 **다른 컬렉션**에 둬야 한국 쪽이 정말로 "아무것도 안 바뀐다".

### 1-3. 화면

- 자산 탭의 보상 마켓·쿠폰 보관함(`js/reward-market.js`). 문구가 전부 한국어이고, 영어 앱(`/en`)에서도 그대로 보인다.
- 플레이 앱(`/app`)은 HBT 만 잠그고 보상 마켓은 보여 준다. 이번 단계에서 HBT 는 건드리지 않는다.

### (다) 둘 다 — **추천**

배지·레벨은 오늘 바로 줄 수 있고, 기프트카드는 업체 가입·테스트·충전이 필요해 시간이 걸린다.
둘을 단계로 나누면 해외 회원에게 "모은 포인트가 헛되지 않다" 를 먼저 보여 주고, 실제 수요를 보고 돈을 쓸 수 있다.

### 2-1. 숫자로 본 문제 — 해외 회원이 첫 보상까지 걸리는 날

1P = 1원, 1달러 ≈ 1,400원(가정, 실제는 교환 시점 환율), 카드 충전 수수료 3% 로 계산.

| 보상 | 필요한 포인트 | 하루 80P 를 매일 받을 때 |
|---|---|---|
| 한국 첫 쿠폰(지금) | 1,400P | 18일 |
| 미국 Target·가상 Visa $1 | 약 1,450P | 19일 |
| 미국 Amazon $5 | 약 7,200P | 90일 |

$1~$2 짜리를 두면 한국 첫 쿠폰과 비슷한 속도가 된다. Amazon $5 만 두면 석 달이 걸린다.
또 회사 비용은 한국이 액면가의 94%(1,880/2,000), 해외는 103%(액면가 + 카드 3%)로 **해외가 1P 당 약 10% 더 비싸다.**

### 2-2. 법·세금·개인정보 (공식 문서 확인분 + 확인 안 된 것)

- **미국 세금 신고(1099):** Tremendous 공식 도움말 — 2026-01-01 지급분부터 신고 기준이 **연 $2,000** 으로 올랐다.
  해외 회원 한 명이 1년 내내 매일 80P 를 받아도 약 29,200P ≈ **$20** 라 기준의 1% 수준이다.
  한국 회사가 미국 회원에게 주는 보상에 1099 의무가 생기는지 자체는 확인하지 못했다 → 세무사 확인.
  Tremendous 세금 기능은 "미국 수령자만" 다룬다고 공식 문서에 적혀 있다.
- **수령자 신원확인(KYC):** 확인한 공식 문서 어디에도 기프트카드 **수령자** 신원확인 요구는 없었다.
  확인 대상은 **우리 회사**(KYB, 제재 명단 대조)다. Reloadly 약관은 회사 정보를 OFAC 명단과 대조한다고 적었고,
  Giftbit 은 활성화 전 KYB 를 요청할 수 있다고 적었다.
- **개인정보 국외 이전(한국 개인정보보호법 제28조의8):** 링크 방식(`LINK`)으로 주문하면 우리가 업체에 **이메일·전화번호를 넘기지 않아도 된다**
  (Tremendous 주문 API 에서 수령자 정보는 필수가 아니다). 그래도 회원이 업체 사이트에서 쿠폰을 고를 때 업체가 IP 등을 받으므로,
  개인정보처리방침에 "국외 이전 — Tremendous(미국), 항목, 목적" 을 넣어야 한다. 지금 KT 알파 문구 옆에 추가하는 방식. 문구는 대표 확인.
- **한국 쪽 세금:** 소득세법상 상금·경품 기타소득은 건별 5만원 이하면 과세하지 않는 것으로 알고 있다. 해외 보상도 몇 달러라 같은 범위로 보이지만
  비거주자 지급이라 세무사 확인을 권한다.
- **외화 송금:** Wise 는 지금 **은행 계좌에서 원화를 Wise 로 넣을 수 없다**(이미 Wise 안에 원화가 있을 때만 원화로 보낼 수 있다 — Wise 공식 도움말).
  Tremendous 가 권하는 "Wise 로 USD 송금" 이 한국 회사에는 막혀 있는 셈이라, 충전은 사실상
  **법인카드(3%)** 가 현실적이다. 은행 송금으로 미국 계좌(ACH)에 넣을 방법이 있으면 0% 가 된다 → 거래 은행 확인.

  "포인트를 기프트카드로 바꾸는 앱" 이 허용 용도인지. **대표가 테스트 계정(testflight, 무료)을 만들어 보면 대부분 바로 확인된다.**

## 3. 설계안

### 원칙

1. **한국 기프티쇼 경로는 파일째 건드리지 않는다.** `functions/reward-market.js` 와 기존 콜러블(`redeemRewardCoupon` 등)은 diff 0.
2. 해외 교환은 **새 모듈 · 새 컬렉션 · 새 콜러블.** 한국 서비스 전체 한도(`reward_redemptions` 합계)에 섞이지 않는다.
3. 포인트 차감·환불만 한국과 같은 방식(원장 기록 + `coins` 증감, live 일 때만 차감 — 교훈 197).
4. 돈이 나가는 응답은 상태까지 확인한다(교훈: 기프티쇼 HTTP 200 안의 오류). 실패하면 포인트를 돌려준다.

### 누가 해외 보상을 보나

- `users.timeZone` 이 있고 `Asia/Seoul` 이 아니면 자산 탭에 **해외 보상 카드**를 보여 준다(서버가 정하는 값, 30일 잠금).
- 한국 기프티쇼 마켓은 **지금처럼 모두에게** 그대로 둔다(해외 한인도 한국 번호가 있으면 쓸 수 있다).
- 실제로 어느 나라 상품이 나오는지는 Tremendous 가 교환 순간 IP 로 정한다. 우리는 나라를 저장하지 않는다.

### 단계

**2-A. 돈 없는 보상 (업체 가입 전, 바로 가능)**
- 해외 회원 자산 탭: "포인트는 그대로 쌓여요. 해외 보상은 준비 중이에요" + 기존 배지·레벨을 앞으로.
- "해외 기프트카드를 원해요" 버튼으로 수요를 센다(새 컬렉션 하나, 서버 함수로만 기록 → 규칙 변경 없음).
- 영어 문구 포함. 화면 변경이라 에셋 버전 v517.

**2-B. Tremendous 연결 — 테스트 모드만 (스테이징)**
- `functions/global-rewards.js` (새 파일): 금액표, 한도 계산, Tremendous 주문·상태 조회, 응답 검증.
- 콜러블 `redeemGlobalReward`, `getGlobalRewardSnapshot`. 비밀키는 `defineSecret("TREMENDOUS_API_KEY")`.
- 컬렉션 `global_reward_redemptions/{req_uid_requestId}` (서버만 씀. 앱은 콜러블로 읽음 → **규칙 배포 필요 없음**).
- 모드: `mock`(가짜 링크) → `sandbox`(testflight) → `live`. mock·sandbox 는 포인트를 차감하지 않는다(교훈 197).
- 주문: `delivery.method = LINK`, `external_id = 요청 문서 ID`(중복 주문 방지), 받은 링크를 우리 보관함에 저장.
- 검증: 주문 상태 `EXECUTED` + 링크 존재. `PENDING APPROVAL`/`PENDING SETTLEMENT` 은 "처리 중"(포인트 유지·관제탑 표시), `FAILED`·`CANCELED` 는 환불.
- 한도(한국과 별개): 서비스 전체 월 달러 한도(대표가 정함) + 회원 한 명 월 한도.

**2-C. 소수 나라 실제 지급 (운영)**
- 처음 나라: 미국·캐나다·영국·호주(작은 금액 상품이 많은 곳). 나머지는 수요 버튼 숫자를 보고.
- 관제탑에 해외 교환 목록·잔액·환불 버튼(교훈 195: 운영 버튼은 관제탑에).
- 개인정보처리방침 국외 이전 문구 추가.

### 테스트 먼저 (구현 첫 커밋)

한국 회원 기프티쇼가 그대로임을 묶는 테스트를 **코드보다 먼저** 쓴다.

1. `buildRewardMarketConfig`·`quoteCatalogItem`·`buildLimitSummary`·첫 교환 할인 결과를 지금 값으로 고정(골든 값).
2. `loadIssuanceUsage` 가 `global_reward_redemptions` 문서를 세지 않는다(가짜 DB 에 두 컬렉션을 넣고 확인).
3. `timeZone` 없는 회원·`Asia/Seoul` 회원의 기프티쇼 스냅샷이 지금과 같고, 해외 보상 정보가 붙지 않는다.
4. `functions/reward-market.js` 내보내기 목록이 그대로다.
5. 해외 쪽: mock 모드는 포인트를 안 깎는다 / 같은 요청 두 번 = 주문 한 번 / `FAILED` 면 환불 / 응답 200 이어도 링크 없으면 실패.

   그리고 금액 단계: 추천 $1 · $2 · $5 · $10.

## 7. 배지를 왜 모으나 — 소장 욕구 설계안 (대표 확인 필요)

지금 배지는 자산 탭 안에서만 보인다. 다른 사람에게 보이지 않으면 살 이유가 약하다.

**핵심: 대표 배지 하나를 골라 이름 앞에 단다.** (`users.displayBadge`, 서버 함수로만 바꿈 — 가진 배지만 고를 수 있음)

| 붙는 곳 | 보는 사람 | 필요한 일 | 난이도 |
|---|---|---|---|
| **카톡 단톡방 챗봇** `!순위`·`!반현황` 등 이름 앞 (`habitchatbot` 저장소 `commands/ranking.js` 등) | 단톡방 전체 | 챗봇 서버가 이미 관리자 권한으로 `users` 문서를 읽는다 → 규칙 변경 없음. 챗봇 저장소 수정 + Render 배포 | 쉬움 |
| 앱 갤러리 게시물·댓글 이름 앞 | 앱 회원 전체(한국어 앱. 영어 앱엔 갤러리 없음) | 앱은 다른 회원 문서를 못 읽는다 → 서버가 쓰는 공개용 `member_badges/{uid}` + 읽기 규칙 추가 → **규칙 배포 별도 승인** | 보통 |
| 소모임 멤버 목록·인증 | 같은 소모임 | 위와 같은 공개용 데이터 사용 | 보통 |

**소장 욕구를 만드는 장치**
1. 희소성 — 배지마다 "보유자 N명" 표시. 👑 같은 비싼 배지는 숫자 자체가 자랑이 된다.
2. 기간 한정 배지 — 이달에만 살 수 있는 시즌 배지(예: 10월 🎃). 놓치면 다시 못 산다.
3. 기록으로만 얻는 배지 — 포인트로 못 사고 30일 연속 기록 등으로만 받는다. 산 배지와 구분돼 더 귀하다.
4. 모으기 완성 보상 — 전부 모으면 이름 앞 배지에 특별 테두리·칭호.

**추천 순서:** ① 대표 배지 + 챗봇 이름 앞 + 보유자 수(규칙 배포 없음) → ② 갤러리·댓글(규칙 배포) → ③ 시즌·기록 배지.

**하나 더:** 국내 회원에게도 열면서 🌍 "세계 회원 — 해외에서 함께해요" 배지가 국내 회원 목록에도 보인다.
국내에서는 숨길지, 이름을 바꿀지 정해야 한다.
