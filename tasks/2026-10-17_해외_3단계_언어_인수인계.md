## 3단계에서 할 것 — 코드로 확인한 출발점

### A. 영어 앱 기능 차이 (가장 급함)
- `styles-en.css` 398~408행: `html.locale-en` 에서 `#dashboard`, `#assets`, `#gallery`, 포인트 배지(`#point-badge-ui`), 퀘스트 보드 등을 `display: none !important`.
- 결과: 영어 앱 회원은 **해빛 배지·투표(자산 탭)**, 갤러리, 대시보드(건강 점수·응원 피드)를 못 본다. 포인트를 모아도 쓸 곳이 안 보인다.
- 메모리 기록: 영어 앱에는 응원 피드·건강 점수·초대 포인트·자랑 버튼이 없다. 영어 앱 회원의 식단·운동·수면은 갤러리에 공개되고, 감사 일기(`gratitudeLocale: 'en'`)는 공개하지 않는다(2026-10-15 대표 결정).
- 해빛 배지 카드(`js/global-rewards.js`)는 영어 문구를 이미 갖고 있다(`copy(ko, en)`). 자산 탭을 영어로 열 때 기프티쇼 마켓(한국 매장 쿠폰)은 어떻게 할지 함께 정해야 한다.

### B. 첫 화면 언어
- `js/app-mode.js`: `/en` 이면 영어, 나머지(`/`, `/app`, `/simple`)는 한국어. `navigator.language` 를 읽는 코드가 없다.
- 플레이 앱은 TWA 로 `/app` 을 연다. 시작 주소를 바꾸면 AAB 를 새로 올려야 한다 → 웹에서 기기 언어를 보고 `/en` 으로 안내·이동하는 방법을 먼저 찾는다.
- TWA 로 열리면 sessionStorage 표시(`hasStickyPlayContext`, `isPlayModeActive`)로 `/`·`/simple`·`/en` 으로 옮겨도 HBT 잠금이 유지된다 — 이것을 깨지 말 것.

### C. 번역 구조 (`js/i18n.js`, 681줄)
- `MESSAGES` = { ko, en } 키 사전(약 320줄), `ENGLISH_TEXT_REPLACEMENTS`(한국어 문장 → 영어 문장 약 144쌍),
  `SELECTOR_TEXTS`/`SELECTOR_TEXTS_ALL`/`SELECTOR_ATTRS`(선택자로 글자 바꾸기), `installLocaleDomObserver`(DOM 변화 감시 후 바꿔치기).
- 코드 곳곳의 `isEnglishLocale() ? '영어' : '한국어'` 분기: `js/app-core.js` 347곳, `js/auth.js` 68곳, `js/diet-analysis.js` 15곳, `js/global-rewards.js` 5곳.
- `/en/index.html` 은 `npm run build:en`(scripts/generate-en-entry.js)으로 만든다. `index.html` 을 바꾸면 `npm run check:en` 이 통과해야 한다.
- 언어를 하나 더 늘리기 어려운 구조다. 목표는 키 기반(ko·en·…)으로 화면 단위 이전.

### D. 커뮤니티 언어
- 갤러리는 한 곳(`gallery_posts`)이다. 영어 앱엔 갤러리 탭이 없다. 언어별 분리·표시 필터·번역 표시 등 선택지 정리가 필요하다.

## 지킬 것 (이 프로젝트 규칙 요약 — 원문은 CLAUDE.md)

- 한국어 앱 화면·기프티쇼 교환은 바뀌지 않는다. 테스트로 먼저 묶는다(예: `tests/global-rewards-korea-unchanged.test.js` 방식).
- 화면을 바꾸면 에셋 버전을 올린다(지금 v521). `index.html` 을 바꾸면 `npm run build:en` → `npm run check:en`.
- 테스트는 `npx vitest run` 전부 통과(2026-10-17 기준 2,919개). 워크트리에서는 `node_modules`, `functions/node_modules` 를
  메인 폴더 것에 junction 으로 연결하고, 끝나면 `cmd /c rmdir` 로 **링크만** 지운다.
- 배포: 스테이징 먼저("스테이징" 이라고 할 때만), 운영은 대표가 말할 때만. Functions 와 hosting 은 따로 올리고 로그를 파일로 남겨
  함수마다 `Successful` 줄을 확인한다(한도 재시도로 1~5개가 빠지는 일이 잦다 → 빠진 것만 다시). 새 함수가 있으면 functions 를 먼저.
- 새 Firestore 필드 → `firestore.rules` 화이트리스트 + 규칙 배포 별도 승인. 서버만 쓰는 필드는 화이트리스트에 넣지 않는다.
- 윈도우에서 Python 으로 파일을 고치면 `newline=''`. 긴 Python 을 Bash heredoc 으로 넘기면 실패할 때가 있다 → 스크립트를 파일로 써서 실행.
