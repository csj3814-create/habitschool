# 웹 앱이 본 앱, 플레이 앱은 걸음수·수면 도우미 — 1단계 설계안

2026-11-02. 구현 전에 대표 확인을 받는다.

> 대표: "헬스커넥트 연동도 HBT 만큼이나 꽤 큰 기능이어서 포기하기 아까운데... 결국 두 앱을 다 설치하도록 권유해야 할까?"
> → 추천: 두 앱을 똑같이 권하지 않는다. 웹 앱(PWA)이 본 앱이고, 플레이 앱은 Health Connect 값을 가져오는 도우미로
>   **안드로이드 웹 회원에게, 걸음수·수면을 넣는 자리에서만** 권한다. 대표: "1단계 설계해 줘"

## 1. 지금 상태 (코드로 확인)

| | 플레이 앱 | 웹 앱 |
|---|---|---|
| Health Connect 걸음수·수면·운동·체성분 | 읽는다. **앱을 열 때마다 그날 기록에 자동 저장**한다(`js/health-connect-autosave.js`, 2026-10-14). 직접 넣은 값은 덮지 않는다 | 못 읽는다(안드로이드 앱만 쓸 수 있는 기능) |
| 공유로 받아 오기 | 된다 | 안드로이드에서 홈 화면에 설치하면 된다(`manifest.json` `share_target`) |
| HBT | 없다 | 있다 |

- 두 앱은 같은 계정·같은 기록이다. **플레이 앱을 한 번 열면 그날 걸음수·수면이 저장되고, 웹 앱에서도 그대로 보인다.**
- 웹 앱에는 이미 "앱에서 최신 걸음수 가져오기" 단추가 있다(`shouldOfferStepRefreshFromWebApp`, 운동 탭 걸음수 띠).
  그런데 (1) 전에 Health Connect 로 걸음수를 받아 본 사람에게만 뜨고, (2) 누르면 플레이 앱이 값을 읽은 뒤 **플레이 앱 안에서**
  결과 화면을 연다(`HealthConnectPermissionActivity.openExercise` → `AppRoutes.twaIntent`). 웹 앱으로 돌아오지 않는다.
- 플레이 앱 안에서는 웹 앱을 권하지 않는다(HBT 단추와 같은 이유, 설계 `2026-11-02_가입_안내_끝_첫기록_설계.md` 8-2절).
  반대 방향 — 웹 앱이 플레이 앱을 도우미로 권하는 것 — 은 플레이 정책과 무관하다.

## 2. 설계

### 2-1. 누구에게, 어디서

- **안드로이드 웹 회원만**(웹 앱으로 설치했든 브라우저든). 아이폰·컴퓨터·플레이 앱 안에서는 그리지 않는다. 한국어·영어 모두.
- **운동 탭 걸음수 칸 아래**(`#step-import-banner` 자리 근처)와 **마음 탭 수면 칸 아래**(`#sleep-hc-btn` 자리 근처). 두 곳 모두 같은 카드.
- 가입 안내·첫 기록 결과 창에서는 권하지 않는다(그때는 "오늘 먹은 사진 하나", 그다음은 웹 앱 설치).
- **오늘 걸음수가 이미 Health Connect 에서 왔으면 카드를 그리지 않는다** — 도우미를 이미 쓰는 사람이다. 그때는 지금 있는
  "Health Connect ○○보 반영됨" 띠가 보인다.
- 닫기(✕)를 누르면 30일 동안 다시 안 뜬다(기기에 기억).

### 2-2. 카드 문구 (영상 말투 기준, `marketing/WRITING_VOICE.md`)

**도우미 앱이 아직 없을 때**
> **걸음수·수면을 자동으로 받고 싶다면**
> Google Play의 해빛스쿨 앱을 도우미로 깔아 두고 하루 한 번 열어 주세요. 열 때마다 Health Connect의 걸음수·수면·운동이
> 저장되고, 여기서도 그대로 보여요. 기록이랑 포인트, HBT는 지금처럼 이 앱에서 하시면 돼요.
> [도우미 앱 받기]  ✕

**도우미 앱이 이미 깔려 있을 때**(`navigator.getInstalledRelatedApps` 로 감지 — `manifest.json` 의 `related_applications` 에 플레이 항목이 이미 있다)
> **도우미 앱을 열면 오늘 걸음수·수면이 저장돼요**
> 저장되는 걸 확인하고 이 앱으로 돌아오시면 돼요.
> [도우미 앱 열기]  ✕

- "도우미 앱 받기": 플레이 스토어 해빛스쿨 페이지(안드로이드 intent, 안 되면 스토어 주소).
- "도우미 앱 열기": 플레이 앱을 연다. 열리면 앱이 늘 하던 대로 Health Connect 값을 읽어 자동 저장한다.
- 감지가 안 되는 브라우저(삼성 인터넷 일부 등)에서는 "받기" 카드를 보인다. 이미 깔려 있으면 스토어가 "열기" 를 보여 준다.

### 2-3. 겹치는 것 정리

- 운동 탭 걸음수 띠의 "앱에서 최신 걸음수 가져오기" 단추(`openStepSyncInAndroidApp`)는 이 카드와 같은 일을 한다.
  두 길을 두지 않고 **카드 하나로 합친다**(띠는 "○○보 반영됨" 안내만 남긴다).

### 2-4. 재는 것

- 카드를 누르면 `settings.healthHelperTapDate`·`settings.healthHelperTapCount`(이미 회원이 쓰는 `settings` 맵 — 규칙 변경 없음).
- 도우미로 실제 넘어왔는지는 이미 남는 `settings.firstAppOpenDate`(플레이 앱을 처음 연 날)와 그날 기록의 걸음수 출처(`health_connect`)로 본다.
- 2~3주 뒤: 안드로이드 웹 회원 중 플레이 앱도 연 사람 수, Health Connect 걸음수가 들어온 웹 회원 수.

### 2-5. 바뀌지 않는 것

- 플레이 앱(새 AAB 없음), 서버, 규칙.
- 웹 회원에게 플레이 앱을 **본 앱으로** 권하지 않는다는 결정(8-2절) — 이 카드는 "도우미" 로만, 걸음수·수면 자리에서만 말한다.
- 가입 안내·첫 기록 뒤 권유(웹 앱 설치).

## 3. 테스트 먼저

- 안드로이드 웹에서만 그린다(아이폰·컴퓨터·플레이 앱 안에서는 없음).
- 오늘 걸음수 출처가 `health_connect` 면 그리지 않는다.
- 감지 결과(깔림/안 깔림/모름)에 따라 "열기"/"받기" 문구가 갈린다.
- 닫으면 30일 동안 안 뜬다.
- 운동 탭 걸음수 띠에서 옛 "앱에서 최신 걸음수 가져오기" 단추가 빠진다.
- 누름 기록은 `settings` 안에만 쓴다.
- 한국어 글자 기준 파일은 더해진 것만 있다(옛 단추 문구만 빠진다).

## 4. 나중 단계 (이번 범위 밖)

- 2단계: 플레이 앱이 뒤에서 Health Connect 값을 서버로 올려, 도우미 앱을 열지 않아도 웹 앱에 채워지게 한다
  (앱 로그인·백그라운드 읽기 권한·플레이 건강 권한 신고·새 AAB 필요).
- 3단계: 한 앱으로 합치기(플레이 앱에 HBT) — 조직 계정·금융 기능 신고·국내 규제 확인이 먼저다.
