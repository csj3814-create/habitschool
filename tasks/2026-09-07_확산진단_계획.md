## 먼저 — 코드를 읽다 찾은 것 (측정 전에 이미 확정)

**카카오톡·인스타·페북·X·블로그로 공유하면 초대 코드가 링크에서 사라진다.**

`publishShareCardForPreview()` 는 카드 문서를 `share_cards/{token}` 에 쓰는 함수다.
호출되는 곳은 딱 세 군데다:

- `js/app-core.js:21781` — Web Share(파일) 경로
- `js/app-core.js:21816` — `shareViaSystem`
- `js/app-core.js:21899` — `copyShareLink`

그런데 **플랫폼 모달 경로 `shareFileToAppsOrFallback()` (`js/app-core.js:21904`)
에는 이 호출이 어느 분기에도 없다.** 카카오·인스타·페북·X·블로그가 전부 이 함수를 탄다.

이 경로도 `getShareTargetUrl()` 로 `/c/{token}` 주소를 만들어 내보낸다
(`js/app-core.js:21926`). 그런데 그 토큰의 문서는 발행된 적이 없으므로:

```js
// functions/runtime.js:5203
const snap = await db.doc(`share_cards/${token}`).get();
if (!snap.exists) {
    res.redirect(302, fallbackUrl);   // = `${APP_BASE_URL}/#gallery` — ?ref= 없음
    return;
}
```

받는 사람이 링크를 눌러도 **`?ref=` 가 붙지 않은 맨 갤러리 주소로 떨어진다.** 그러면:

1. `processReferralSignup` 이 호출되지 않는다 → **귀속 없음, 가입자 200P 없음,
   자동 친구 연결 없음, 초대자 500P 없음**
2. 초대 배너(`index.html:969`)가 안 뜬다 — `?ref=` 로 켜지기 때문
3. `invite_link_landing` GA 이벤트가 초대로 안 잡힌다
4. 카카오 경로는 미리보기도 정적 이미지로 고정이다 —
   `imageUrl: APP_OG_IMAGE_URL` (`js/app-core.js:21949`). 카드별 OG 를 만든 이유
   (*"열 명이 각자 다른 카드를 공유해도 미리보기가 전부 같아서 두 번째부터는 아무도
   안 누른다"* — `runtime.js:5165`) 가 **카카오에서만 그대로 살아 있다.**

`copyShareLink` 에 붙은 주석 *"링크만 보내는 경우에도 미리보기가 붙어야 한다"* 로 보아
의도가 아니라 누락이다. 한국에서 공유는 사실상 카카오톡이므로, **8월 초대 성공 0건의
상당 부분이 이 한 줄일 수 있다.**

단, "이것 때문이다"라고 단정하지 않는다. 아래 측정이 이걸 확인해 준다 —
GA 의 `share_card_sent` 총건수와 `share_cards` 문서 수를 나란히 놓으면
"공유는 나갔는데 카드가 발행 안 된 건수"가 그대로 드러난다.

### 재는 것

**1. 활성화 — 새는 곳이 여기인지부터**
- 가입 코호트(월별)별: 가입자 수 / 기록을 한 번이라도 한 비율 / 3일 이상 비율 / 지금도 활성인 비율
- **평생 기록일수 분포**: 0일 / 1일 / 2일 / 3–6일 / 7–29일 / 30일+
  → 0–1일이 절반을 넘으면 병목은 잔존이 아니라 **첫 기록**이다

**2. 잔존** — 가입일 기준 D1 / D7 / D30. 어느 날에 꺾이는지

**3. 초대 퍼널 (Firestore 쪽 진실)**
- `users.referredBy` 보유자 수 — 월별
- `users.referralDay3BonusGiven` / `referralDay7BonusGiven` 수
- `friendships` 를 `source` 별로: `invite_link_signup` / `invite_link_existing` / 그 외

**4. 실제로 나간 공유 — 위 가설의 검증**
- `share_cards` 문서 수 + 고유 `userId` 수 (30일 TTL 이라 최근 30일치)
- 이 값은 **하한**이다. 플랫폼 모달 경로는 문서를 안 만들기 때문.
  GA 의 `share_card_sent` 와의 **차이가 곧 코드 코드가 빠진 공유 건수**다

**5. 혼자 하는 구조인지**
- 활성 회원 중 친구 1명 이상 보유 비율
- `habit_group_members` 그룹별 인원
- 이번 달 댓글·리액션을 **남긴** 고유 인원 (`gallery_posts` 기준 —
  `functions/mvp-score.js` 가 경고하는 대로 `daily_logs` 를 읽지 않는다)

### 비용

`daily_logs` 전체 1회 스캔(필드 마스크 `userId`, `date`, `awardedPoints`) +
`users` 1회 스캔(579건). `users.lastLogDate` 가 9/1 에 백필돼 있어 잔존 계산이 싸다.
`computeCommunityStats` 가 매시간 두 달치를 읽는 것에 비하면 1회성으로 무시할 수준.
